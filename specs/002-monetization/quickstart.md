# Quickstart: проверка монетизации (002)

Сценарии, которыми проверяется готовая функция. Детали полей — в
[contracts/api.md](contracts/api.md) и [data-model.md](data-model.md).

## Подготовка

```bash
# server/.env (локально)
PAYMENTS_PROVIDER=fake          # платежи без ЮKassa; «Оплатить/Отменить» на экране «Баллы»
MAIL_TRANSPORT=log              # письма в лог, подтверждение почты включено
ROUTE_MONTHLY_LIMIT=2           # чтобы быстро выйти за бесплатный лимит

npm --prefix server run dev
npm --prefix app run web
```

Автотесты и проверки (принцип VII):

```bash
npm test             # сервер: в т.ч. test/money.test.ts, test/paid-routes.test.ts
npm run typecheck    # сервер и приложение
npm --prefix app run lint
```

Тестовый магазин ЮKassa (перед выкладкой): `PAYMENTS_PROVIDER=yookassa`, shopId и ключ
тестового магазина, уведомления на адрес, доступный из интернета; тестовые карты — из
документации ЮKassa.

## Сценарии

### 1. Покупка баллов (US1, FR-004, SC-001)
1. Пользователь A подтверждает почту → «Профиль» → «Баллы» → купить 300.
2. Fake: «Оплатить». **Ожидается**: 300 баллов, операция «Покупка баллов» в истории,
   в логе — письмо-чек отсутствует (чек присылает ЮKassa), в тестовом магазине — чек в ЛК.
3. Повторить с «Отменить». **Ожидается**: баллы не изменились, сообщение об отмене.
4. Отправить уведомление `payment.succeeded` дважды (тест). **Ожидается**: начисление одно.

### 2. Бесплатный лимит и платная генерация (US1, FR-005…FR-009)
1. A создаёт 2 маршрута с рассказами и озвучкой. **Ожидается**: «бесплатно, осталось N из 2»,
   списаний нет.
2. Третий маршрут на 3 часа. **Ожидается**: цена 50 до запуска; после готовности −50;
   рассказы не создаются сами, предлагается «Рассказы для 8 мест — N баллов».
3. Заказать рассказы. **Ожидается**: списание ≤ показанной сумме; если для точки рассказ
   не создался — за неё не списано (тест с ошибкой ИИ).
4. Подбор, завершившийся ошибкой «нет мест». **Ожидается**: резерв снят, баллы на месте.
5. Перезапустить сервер во время задачи. **Ожидается**: задача продолжилась, повторного
   резерва нет (тест).
6. Сменить `PRICE_STORY` в админке между показом цены и подтверждением. **Ожидается**:
   `409 PRICE_CHANGED`, клиент показывает новую цену.

### 3. Платный маршрут (US2, FR-012…FR-017, SC-005)
1. Автор B публикует маршрут, ставит цену 100. **Ожидается**: «на проверке», в каталоге нет.
2. Администратор: «Проверка маршрутов» → одобрить. **Ожидается**: письмо B, маршрут в
   каталоге с ценой 100.
3. A (без покупки) открывает маршрут. **Ожидается**: превью без точек, карты и рассказов;
   экспорт GPX — 404; ссылка на озвучку без подписи — 403; рассказы этого маршрута не
   подставляются в новый маршрут A по тому же месту.
4. A открывает за 100. **Ожидается**: −100 у A, +80 у B, +20 выручки; полный маршрут;
   оценка доступна.
5. B удаляет маршрут. **Ожидается**: у B маршрута нет, у A — есть с пометкой.

### 4. Премия (US3, FR-018…FR-022)
1. A со страницы бесплатного маршрута B отправляет 50 с сообщением. **Ожидается**: −50 у A,
   +40 у B, в истории B — имя A, маршрут и сообщение.
2. B на своём маршруте не видит кнопку «Поддержать»; API на премию себе — 400.

### 5. Вывод (US4, FR-024…FR-024d)
1. B подаёт заявку на 500. **Ожидается**: до подачи «к выплате 475 ₽, комиссия 25 ₽»;
   после — 500 заморожено, потратить их нельзя.
2. Администратор отмечает «выплачено». **Ожидается**: письмо B, баллы списаны.
3. Повторить с «отклонено». **Ожидается**: баллы вернулись в доступные.

### 6. Админка и сверка (US5, FR-026…FR-029, SC-003)
1. «Деньги» → сводка за период. **Ожидается**: `reconciled = true` после всех сценариев.
2. Возврат 100 баллов по платежу A через ЮKassa (тестовый магазин). **Ожидается**: −100 у A,
   статус возврата `succeeded`, чек возврата в ЛК ЮKassa.

### 7. Без ЮKassa
`PAYMENTS_PROVIDER` пуст. **Ожидается**: приложение работает как до функции; сверх лимита —
прежнее сообщение о лимите; цен и кнопок покупки нет.

### 8. iOS
Сборка iOS: экран «Баллы» показывает остаток и историю, кнопки «Купить» нет; открыть
платный маршрут за имеющиеся баллы можно.
