# Implementation Plan: Монетизация — платная генерация, платные маршруты и поддержка авторов

**Branch**: `002-monetization` | **Date**: 2026-11-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-monetization/spec.md`

## Summary

Вводится единая валюта — баллы (1 ₽ = 1 балл), которые покупаются только через ЮKassa и
тратятся на генерацию сверх бесплатного лимита (5 маршрутов в месяц вместе с рассказами и
озвучкой), открытие платных маршрутов и премии авторам; любые баллы выводятся по заявке
с комиссией 5 %, которую вручную исполняет администратор.

Технически: журнал с двойной записью и резервами в той же SQLite (R1–R3), шлюз ЮKassa на
`fetch` без SDK с идемпотентным начислением по сверке статуса через API (R4–R6),
подтверждение цены клиентом (`expectedCost`, R9), закрытие содержимого платных маршрутов на
всех путях, включая подписанные ссылки на медиа и исключение из переиспользования рассказов
(R10), мягкое удаление проданных маршрутов и обезличивание авторов (R11), проверка платных
маршрутов администратором (R12). Всё денежное выключается одной настройкой
`PAYMENTS_PROVIDER`, поэтому код выкатывается до подключения магазина.

## Technical Context

**Language/Version**: TypeScript 5 (строгий режим) — сервер на Node.js 24 (запуск `.ts`
напрямую), клиент на Expo SDK 58 / React Native.

**Primary Dependencies**: Fastify 5, zod 4, `node:sqlite`, nodemailer; клиент — expo-router,
expo-linking. Новых зависимостей нет: ЮKassa — через `fetch`, длительность mp3 — разбором
кадров, подписи медиа — `node:crypto`.

**Storage**: SQLite (`/var/lib/rasskazhi/rasskazhi.sqlite`), новые таблицы и колонки — в
[data-model.md](data-model.md); файлы медиа — локальный диск, как сейчас.

**Testing**: `node --test` (сервер, `app.inject`), fake-шлюз платежей; клиент — `tsc` и
`expo lint`; ручные сценарии — [quickstart.md](quickstart.md); перед выкладкой — тестовый
магазин ЮKassa.

**Target Platform**: Linux VPS (systemd + Caddy), веб, Android; iOS — без покупки баллов.

**Project Type**: мобильное/веб-приложение + API (монорепозиторий `server/` + `app/`).

**Performance Goals**: зачисление баллов < 2 мин после оплаты в 95 % случаев (SC-001);
платные действия добавляют к запросу не больше одной транзакции SQLite (< 5 мс).

**Constraints**: один процесс сервера и одна SQLite — атомарность через транзакции без
распределённых блокировок; уведомления ЮKassa не подписаны — доверяем только API;
`<audio>`/`<img>` не передают заголовок авторизации — подписанные ссылки.

**Scale/Scope**: десятки–сотни пользователей, до тысяч операций в месяц; ~25 новых
endpoints (включая админку), 4 экрана клиента (Баллы, страница автора, оферта, 3 раздела админки) и правки
экранов создания, маршрута и профиля.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Принцип | Проверка | Итог |
|---|---|---|
| I. Пользовательская ценность, мобильный приоритет | Цена видна до каждого действия, покупка/премия ≤ 3 действий (SC-006); веб и Android — полностью; iOS — без покупки, остальное работает (документировано в спеке) | ✅ |
| II. Достоверность геоданных | Подбор маршрута не меняется; цена считается от бюджета прогулки кодом | ✅ |
| III. ИИ под контролем кода | Платность не влияет на валидацию ответов ИИ; при сбое ИИ резерв снимается, списание только за результат | ✅ |
| IV. Источники и атрибуция | Превью платного маршрута показывает обложку с атрибуцией Commons; закрытие содержимого не убирает атрибуцию у тех, кто имеет доступ | ✅ |
| V. Безопасность и приватность | Ключ ЮKassa — секрет в настройках, маскируется в админке; реквизиты выплат не храним; доступ к платному содержимому — на сервере (R10); негативные тесты на доступ, премию себе, чужой платёж, подделку уведомления; политика дополняется сведениями о ЮKassa | ✅ |
| VI. Надёжность и целостность | Сервер — источник истины для цены (`expectedCost`), остатков и доступа; миграции совместимые; тайм-ауты и сверка ЮKassa; задачи не дублируют резерв после перезапуска; проданные маршруты и журнал не удаляются каскадом (R11) | ✅ |
| VII. Проверяемое качество | Логика денег — в отдельных модулях с юнит-тестами (журнал, цены, mp3-длительность); тесты сценариев на `app.inject`; инварианты журнала проверяются в тестах | ✅ |
| VIII. Совместимость | Без `PAYMENTS_PROVIDER` поведение прежнее; существующие API расширяются полями, не меняются; ссылки на медиа бесплатных маршрутов не меняются; новых зависимостей нет | ✅ |
| Эксплуатация | Перед выкладкой — копия базы (миграция схемы); уведомления ЮKassa — через Caddy на тот же домен; fake-шлюз запрещён в production | ✅ |
| Процесс | Работа в ветке `002-monetization` порциями по пользовательским историям | ✅ |

Повторная проверка после Phase 1: нарушений нет. Отдельно отмечено: правило «каждое
изменение авторизации — с негативными тестами» распространяется на новый обработчик
`/media/:file` и `/api/payments/yookassa/notify` — тесты включены в задачи.

вызова в местах генерации и чтения маршрутов.

## Порядок реализации (для /speckit-tasks)

1. **Основа**: схема и миграции, `ledger.ts` + тесты инвариантов, `pricing.ts`, настройки.
2. **US1 (P1)**: `payments.ts` (fake → yookassa), покупка и уведомления, резерв/списание в
   генерации и рассказах, экран «Баллы», цены на экране создания и маршрута.
3. **US2 (P2)**: цена и проверка маршрута, покупка, закрытие содержимого (R10), мягкое
   удаление и обезличивание (R11), админка проверки.
4. **US3–US4 (P3)**: премии и страница автора; заявки на вывод и админка заявок.
5. **US5 (P3)**: сводка и сверка, возвраты, оферта и политика.
6. **Выкладка**: копия базы, тестовый магазин ЮKassa → боевой; настройка уведомлений в ЛК.

## Complexity Tracking

Нарушений конституции нет. Осознанные усложнения:

| Решение | Зачем | Почему не проще |
|---|---|---|
| Двойная запись вместо одного поля баланса | Сверка с ЮKassa и выручкой (SC-003, FR-029) | Одно поле нельзя проверить и объяснить в истории |
| Подписанные ссылки на медиа | Закрыть озвучку и фото платных маршрутов (SC-005) | `<audio>` не умеет заголовок авторизации; переименование файлов не отзывает ссылки |
| Мягкое удаление маршрутов и обезличивание авторов | Бессрочный доступ покупателей (FR-014) | Каскадное удаление уничтожает купленное |
