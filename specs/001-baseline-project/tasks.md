# Задачи по базовому проекту Rasskazhi

**Назначение:** список незакрытых проверок, документационных работ и улучшений, выявленных при чтении архива. Это не список задач на повторную реализацию всех функций из `spec.md`.

Статусы `[ ]` означают, что задача не подтверждена как выполненная в рамках данного анализа. Перед реализацией сверить с актуальной рабочей веткой.

## Phase 0 — подтвердить baseline

- [ ] T001 Сверить `spec.md` с текущей веткой кода и отметить изменившиеся функции. Acceptance: каждое FR имеет ссылку на код/тест либо пометку «требует подтверждения».
- [ ] T002 Устранить расхождения README по сбросу пароля и удалению аккаунта. Acceptance: README соответствует обработчикам `app.ts`, тестам и реальному UX; либо документирует фактическое ограничение.
- [ ] T003 Проверить, что все клиентские сценарии авторизации (forgot/reset/delete) доступны на iOS, Android и Web. Acceptance: описаны подтверждённые экраны и ограничения платформ.
- [ ] T004 Зафиксировать полный контракт API по фактическим Zod-схемам и типам клиента. Acceptance: `contracts/api-contract.md` дополнен схемами ключевых операций и правилами авторизации.
- [ ] T005 Провести ревью миграций SQLite на копии базы. Acceptance: миграции повторно применимы, старые записи сохраняются, есть тесты на поддерживаемые версии схемы.

## Phase 1 — безопасность и пользовательский контент

- [ ] T010 Провести аудит контроля доступа для приватных маршрутов, медиа, фоновых задач и административных API. Acceptance: матрица ролей/ресурсов и негативные тесты на доступ чужого пользователя.
- [ ] T011 Спроектировать и реализовать механизм жалоб на публичные маршруты и материалы. Acceptance: пользователь может отправить жалобу, администратор видит её и может принять решение; события аудируются.
- [ ] T012 Определить правила модерации пользовательских фото, видео и аудио. Acceptance: документированы запрещённые типы/контент, статусы модерации, действия администратора и сроки хранения.
- [ ] T013 Проверить безопасность загрузок: MIME sniffing, расширения, лимиты, имена файлов, хранение вне публичной директории, выдача приватных файлов. Acceptance: угрозы описаны, тесты на обходы и вредоносные форматы добавлены.
- [ ] T014 Проверить сценарии удаления аккаунта и каскадного удаления медиа/маршрутов/сессий. Acceptance: задокументированы удаляемые данные, сроки резервных копий и поведение внешних копий.
- [ ] T015 Провести проверку конфиденциальности при передаче стартовых координат, пожеланий и текстов рассказов внешним AI/TTS провайдерам. Acceptance: privacy notice соответствует фактическим потокам данных.

## Phase 2 — надёжность и эксплуатация

- [ ] T020 Выбрать production-провайдера геокодирования, маршрутизации, Overpass и тайлов. Acceptance: зафиксированы SLA/лимиты/стоимость/атрибуция и конфигурация endpoints.
- [ ] T021 Спроектировать абстракцию объектного хранилища для загружаемых медиа. Acceptance: описаны интерфейс, миграция локальных файлов, приватный доступ и резервное копирование; S3 внедрять отдельной задачей.
- [ ] T022 Подготовить стратегию SQLite backup/restore и проверку восстановления. Acceptance: есть автоматизированная инструкция и тест восстановления на копии.
- [ ] T023 Добавить структурированные логи и метрики фоновых задач/внешних вызовов. Acceptance: можно определить длительность, исход, число повторов и ошибки без утечки секретов/персональных данных.
- [ ] T024 Проверить поведение очереди jobs при аварийном завершении процесса и повторном старте. Acceptance: зафиксированы гарантии выполнения, retry policy, идемпотентность и сценарии зависших задач.
- [ ] T025 Подготовить production deployment runbook: TLS, reverse proxy, TRUST_PROXY, секреты, healthcheck, обновление и rollback. Acceptance: чистая установка разворачивается по инструкции.
- [ ] T026 Добавить CI pipeline для тестов сервера, typecheck клиента/сервера и lint приложения. Acceptance: PR не проходит обязательные проверки при ошибке.
- [ ] T027 Описать нагрузочные пределы и провести базовый load test API/фоновых задач. Acceptance: есть воспроизводимый профиль нагрузки и список узких мест.

## Phase 3 — продуктовая согласованность

- [ ] T030 Проверить доступность и понятность fallback-сценариев ИИ/TTS в UI. Acceptance: пользователь видит, когда маршрут/рассказ сформирован без ИИ или без серверной озвучки.
- [ ] T031 Проверить атрибуцию Wikipedia/Wikimedia в экранах, превью и экспорте. Acceptance: ссылки, авторы и лицензии доступны в соответствующих сценариях.
- [ ] T032 Зафиксировать политику переиспользования рассказов и озвучки. Acceptance: документированы ключи совпадения, story_version, язык, стиль, голос и исключение авторских текстов.
- [ ] T033 Проверить ограничения Google Maps на число промежуточных точек и UX для длинных маршрутов. Acceptance: пользователь получает предсказуемый результат при превышении ограничения.
- [ ] T034 Проверить, что каталог корректно работает с городами, неизвестным городом и ошибками геолокации. Acceptance: тесты покрывают пустое состояние, отказ разрешения и сбой геокодера.

## Phase 4 — решение владельца продукта

- [ ] T040 Принять решение о приоритете офлайн-режима. Acceptance: отдельная спецификация либо явное исключение из roadmap.
- [ ] T041 Утвердить требования к масштабу production и целевому SLA. Acceptance: зафиксированы целевые показатели и соответствующие архитектурные решения.
- [ ] T042 Утвердить сроки хранения и удаления пользовательских данных. Acceptance: политика хранения согласована с реализацией и текстом privacy policy.

## Порядок выполнения

1. Сначала T001–T005: подтвердить актуальность baseline.
2. Затем T010–T015: безопасность и правовые/контентные риски.
3. Затем T020–T027: эксплуатация и масштабирование.
4. T030–T034 можно выполнять параллельно после подтверждения baseline.
5. T040–T042 требуют решения владельца продукта до детализации реализации.

## Правила обновления

- Не отмечать задачу `[x]` только на основании наличия похожего файла или обработчика.
- Для задач безопасности требуются тесты и проверка негативных сценариев.
- Новые задачи, найденные `/speckit-converge`, добавлять в отдельный раздел `Convergence`, не удаляя существующие незавершённые задачи.
