# Исследование текущего репозитория Rasskazhi

## Источники исследования

Анализ выполнен по файлам предоставленного `Rasskazhi.zip`. Основные источники:
- `README.md`
- `package.json`, `app/package.json`, `server/package.json`
- `server/src/*.ts`
- `server/test/*.test.ts`
- `app/src/app/`, `app/src/components/`, `app/src/lib/`
- `docker-compose.yml`, `tts/Dockerfile`, `tts/server.py`
- `server/.env.example`

Не использовались значения из `.env`, содержимое базы данных и пользовательские загрузки. В архиве присутствуют такие runtime-артефакты; их не следует включать в документацию или коммитить без отдельной необходимости.

## Подтверждённые технологические решения

- Клиент — Expo Router + React Native + React Native Web.
- Backend — Fastify + TypeScript, Node.js >=24.
- БД — SQLite через `node:sqlite`, WAL и ручные миграции при открытии.
- Валидация — Zod.
- ИИ — Claude и DeepSeek, общий интерфейс и выбор провайдера через env.
- Геоданные — Overpass/OSM, Wikipedia, Nominatim, OSRM.
- Обогащение мест — Wikidata и Wikimedia Commons.
- TTS — Yandex SpeechKit или OpenAI-compatible `/audio/speech`; контейнер Piper присутствует.
- Почта — Nodemailer/SMTP.
- Тесты сервера — встроенный `node:test`.

## Наблюдаемое тестовое покрытие

`api.test.ts` покрывает AI DeepSeek, источники мест, легенды, экспорт, TTS, выбор AI, геометрию/бюджет, планировщик и API-маршруты.

`features.test.ts` покрывает подтверждение почты, месячный лимит, фото Commons, Wikidata/heritage, повторное использование рассказов/озвучки, превью, миграции, сброс пароля и удаление аккаунта.

`jobs.test.ts` покрывает очередь, ограничение параллельности, восстановление после перезапуска и ошибку.

`admin.test.ts` покрывает роли, пользователей, блокировки, удаление, маршруты, настройки и фоновые сценарии.

Наличие тестов не является доказательством успешного прохождения тестов на момент подготовки документации: команды тестирования в рамках этого документального анализа не запускались.

## Важные расхождения и риски

1. README говорит, что сброс пароля и удаление аккаунта не реализованы. В серверном `app.ts` есть соответствующие endpoints, а `features.test.ts` содержит тесты. Необходимо проверить UI и production-поведение и синхронизировать README.
2. README указывает, что маршруты ограничены 5 в месяц по московскому времени; код `app.ts` содержит месячный лимит и `monthWindow`. Админские настройки и индивидуальный лимит пользователя также существуют.
3. Локальные файлы и SQLite подходят для простой установки, но не обеспечивают автоматически shared state для нескольких backend-инстансов.
4. Публичные геосервисы требуют отдельного production-плана.
5. В архиве есть `.env` и runtime data; перед публикацией репозитория следует проверить gitignore и историю Git на наличие секретов. Значения секретов здесь не анализировались и не воспроизводятся.

## Границы достоверности

- Содержимое `README.md` трактуется как документация продукта, но может отставать от реализации.
- Исходный код подтверждает наличие логики, но не гарантирует, что она доступна в интерфейсе или готова для production.
- Точные JSON-схемы API должны извлекаться из Zod-схем и обработчиков в актуальной ветке.
- Неподтверждённые функции не объявляются реализованными.
