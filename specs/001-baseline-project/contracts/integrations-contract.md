# Контракты внешних интеграций

Сведения основаны на README, `.env.example` и серверных модулях. Конкретные API payloads и версии провайдеров необходимо проверять в коде перед изменением интеграции.

## AI — Claude и DeepSeek

- Общая модель интерфейса и промптов: `server/src/ai.ts`.
- Адаптеры: `ai-claude.ts`, `ai-deepseek.ts`.
- Выбор: `ai-provider.ts`.
- Конфигурация: `ANTHROPIC_API_KEY`, `DEEPSEEK_API_KEY`, `AI_PROVIDER`, модельные параметры.
- AI выбирает из кандидатов, найденных сервером; сервер проверяет выбранные ID.
- Ответы проверяются Zod-схемой.
- Fallback: эвристический выбор мест и резервный текст рассказа.
- Внешнему провайдеру могут передаваться стартовая точка, пожелания и данные, необходимые для рассказа. Это должно быть отражено в privacy policy.

## Геосервисы и контент

| Сервис | Назначение | Модуль |
|---|---|---|
| OpenStreetMap / Overpass | Кандидаты мест и объекты карты | `services.ts` |
| Nominatim | Геокодирование/поиск адреса | `services.ts` |
| OSRM / routing service | Пешая маршрутизация по уличной сети (фактический endpoint проверить в коде) | `services.ts` |
| Wikipedia | Статьи и разделы о легендах | `services.ts` |
| Wikidata | Факты, идентификаторы, культурное наследие | `places.ts` |
| Wikimedia Commons | Фотографии, авторство, лицензия | `places.ts` |

Правила:
- Обрабатывать сетевые ошибки и тайм-ауты.
- Отличать пустой ответ от недоступности источника.
- Не удалять атрибуцию и ссылки.
- Не считать публичные endpoint гарантированно пригодными для production-нагрузки.
- Соблюдать User-Agent и политики соответствующих сервисов.

## TTS

Поддерживаемые варианты, описанные в README:
- Yandex SpeechKit API v3 (`YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_TTS_*`);
- OpenAI-compatible `/audio/speech` (`TTS_BASE_URL`, `TTS_API_KEY`, `TTS_MODEL`, `TTS_VOICE`);
- Piper локальный сервис через Docker Compose.

Модуль: `server/src/tts.ts`; локальный сервис: `tts/server.py`.

Требования:
- Проверять непустой аудиоответ.
- Обрабатывать тайм-ауты и ошибки провайдера.
- Для длинного текста поддерживать разбиение на части (README указывает 4800 символов для Yandex).
- Сохранять голос для корректного переиспользования озвучки.
- При недоступности серверного TTS использовать предусмотренный fallback на голос устройства.

## SMTP

Модуль: `server/src/mail.ts`.
Конфигурация: `SMTP_URL`, `MAIL_FROM`, опционально `MAIL_TRANSPORT=log` для разработки.
Используется для подтверждения email и сброса пароля.
Не логировать пароли, токены в открытом виде и секреты SMTP.

## Интеграции и production

Для каждой интеграции перед релизом зафиксировать:
- endpoint и версию API;
- аутентификацию и секреты;
- тайм-ауты, retry/backoff и rate limits;
- обрабатываемые коды ошибок;
- данные пользователя, передаваемые провайдеру;
- стоимость/лимиты и мониторинг;
- fallback и деградацию;
- лицензионные/атрибуционные условия.
