# Контракт базы данных

См. `../data-model.md`. Этот файл фиксирует правила изменения схемы.

## Источник истины

- SQL schema и миграции находятся в `server/src/db.ts`.
- Не поддерживать вторую независимую схему в документации или ORM без отдельного архитектурного решения.
- SQLite включается в WAL mode; foreign keys включены.

## Правила изменений

1. Любое изменение таблиц выполняется миграцией в `openDb()` / `migrate()`.
2. Миграция должна быть безопасна для уже существующей БД.
3. Миграция должна быть идемпотентной при повторном запуске.
4. Для добавляемого поля определить default/nullability и поведение старых записей.
5. Для новых связей определить `ON DELETE` поведение.
6. Для пользовательских файлов определить отдельную очистку диска: FK не удаляет файлы.
7. Добавить тест на upgrade старой схемы и на сохранность данных.
8. Не использовать реальную пользовательскую БД для тестирования миграций.

## Критичные инварианты

- Рейтинг: 1–5, уникальная пара маршрут/пользователь.
- Точки маршрута имеют позицию.
- Сессии и токены принадлежат пользователю.
- Удаление пользователя/маршрута имеет каскадные последствия для связанных строк.
- Удаление маршрута/пользователя должно согласованно очищать файловые материалы по логике приложения.
- `media.is_narration` и `media.voice` нужны для отличия авторских вложений от TTS-озвучки и для проверки совместимости голоса.
