# Чек-лист качества базовой спецификации

Этот файл — reviewer-owned checklist. Отмечать `[x]` только после проверки качества требований; галочка не означает, что функция реализована.

## Полнота и однозначность
- [ ] У каждого пользовательского сценария определены актор, предусловия, основной поток и ошибки.
- [ ] Требования отделяют поведение продукта от технологии реализации.
- [ ] Для ограничений указаны единицы измерения и границы.
- [ ] Термины «маршрут», «точка», «остановка», «рассказ», «озвучка», «публичный» и «приватный» используются последовательно.
- [ ] Неизвестные правила помечены вопросами, а не заполнены предположениями.

## Геоданные и ИИ
- [ ] Указано, что ИИ выбирает только из реальных кандидатов.
- [ ] Указано, где выполняется серверная валидация выбора ИИ.
- [ ] Описан fallback при недоступности ИИ.
- [ ] Описано различие ошибки источника и отсутствия кандидатов.
- [ ] Для режима легенд исключено выдумывание исторических фактов/преданий.
- [ ] Определены требования к точности маршрута и бюджету прогулки.

## Безопасность и приватность
- [ ] Для каждого приватного ресурса описан контроль доступа.
- [ ] Для загрузок определены ограничения и обработка файлов.
- [ ] Описаны подтверждение почты, сессии, сброс пароля и удаление аккаунта.
- [ ] Описано, какие данные уходят внешним AI/TTS/geo-провайдерам.
- [ ] Указаны правила удаления пользовательских данных и резервных копий.

## Источники и лицензии
- [ ] Для Wikipedia/Wikimedia описана атрибуция.
- [ ] Для Commons сохраняются автор и лицензия.
- [ ] Ошибки необязательных источников не приводят к неоправданному отказу всей функции.

## Проверяемость
- [ ] У каждого FR есть критерии приемки.
- [ ] У каждого требования определён тестовый или ручной способ проверки.
- [ ] API-контракты синхронизированы с серверными Zod-схемами и клиентскими типами.
- [ ] Миграции имеют тесты на старую схему.
- [ ] Различия README и кода разрешены или явно задокументированы.

## Production
- [ ] Определён production-провайдер геосервисов.
- [ ] Описаны HTTPS, reverse proxy и TRUST_PROXY.
- [ ] Описаны резервное копирование и восстановление.
- [ ] Определена стратегия файлового хранилища.
- [ ] Есть политика модерации публичного контента.
